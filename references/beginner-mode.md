# Beginner mode — 미국 규제를 모르는 한국어 사용자

미국 임상·규제 경험이 없고 영어 문서가 부담스러운 한국어 사용자를 위한
설명 모드다. 결론과 다음 행동을 먼저 주고, 전문용어는 그때그때 풀어 쓴다.

## 언제 쓰나

다음 중 하나라도 해당하면 이 모드로 답한다.

- "미국 규제/임상은 잘 몰라요", "주니어 개발자예요", "처음이에요"
- 한국어로 묻고, 영어 약어를 거의 쓰지 않는다
- "이게 뭐야", "왜 필요한 거야", "당장 뭐부터 해야 해"
- 같은 용어를 두 번 이상 되묻는다
- 사용자가 결정을 내려야 하는데 배경지식이 없다고 말한다

## 원칙

1. **결론 먼저.** 첫 3문장 안에 "지금 무엇을 해야 하는가"를 쓴다.
2. **모든 약어를 푼다.** `510(k)`가 나오면 바로 옆에 "미국 FDA의 시판 전
   허가 절차"라고 쓴다. 두 번째부터는 생략 가능.
3. **표는 2~3열, 문장은 짧게.** 긴 법률 문장을 그대로 붙이지 않는다.
4. **"지금은 몰라도 되는 것"을 따로 적는다.** De Novo, PMA, BAA처럼 이번
   결정에 필요 없는 것을 먼저 걷어낸다.
5. **영어 원문을 읽어야 하면 위치를 알려준다.** 예: "510(k) summary의
   `Indications for Use` 섹션만 먼저 보세요."
6. **모르는 것은 모른다고 표시한다.** "확인 필요"와 "가정"을 구분한다.
7. **마지막에 다음 3단계.** 누가, 무엇을, 언제까지.
8. **검색은 영어로, 설명은 한국어로.** 영어 검색어로 조회한 뒤 결과를 한국어로
   풀어 쓴다. `references/query-pipeline.md` 참고.
9. **번역투로 쓰지 않는다.** 영어 문장을 그대로 옮기지 말고 뜻을 살려 다시 쓴다.
   "~에 따라 달라집니다", "~하는 것이 가능합니다", "~가 기준입니다" 같은 표현은
   쓰지 않는다. `references/korean-style.md` 참고.

## 문장은 한국어답게

- 나쁜 예: "앱이 무엇을 한다고 말하느냐에 따라 갈립니다."
- 좋은 예: "앱이 무엇을 한다고 광고하는지 보면 답이 나와요."

- 나쁜 예: "설문 자체보다 점수로 무엇을 하느냐가 기준입니다."
- 좋은 예: "중요한 건 설문이 아니라, 그 점수로 무엇을 하느냐예요."

- 나쁜 예: "추가 임상이 필요합니다."
- 좋은 예: "임상을 더 해야 해요."

초심자 모드에서는 "해요"체를 쓴다. 한 글 안에서 "합니다"체와 섞지 않는다.

## 출력 템플릿

```markdown
## 한 줄 결론
[제품]은 [규제 대상/아님]이고, 지금은 [다음 행동]이 필요합니다.

## 왜 그런가
[비유 1개 + 2~3문장. 전문용어는 괄호로 풀이.]

## 지금 해야 할 일
1. ...
2. ...
3. ...

## 가장 조심할 것
[표현/결정 하나. 예: "진단"이 아니라 "위험 알림".]

## 지금은 몰라도 되는 것
- De Novo: ...
- PMA: ...
- HIPAA B2B: ...

## 용어 사전
| 용어 | 쉬운 말 |
|---|---|
| ... | ... |

## 더 알고 싶을 때
- 영어 원문: [제목] — `Indications for Use` 섹션부터
- 로컬 KB: `kb get ...`
```

## 비유 사전

| 용어 | 비유 |
|---|---|
| predicate | "합격 기준이 되는 선배 제품" |
| 510(k) | "선배 제품과 본질적으로 같다는 것을 FDA에 증명하는 절차" |
| De Novo | "비슷한 선배가 없을 때 새 분류를 만드는 절차" |
| PMA | "가장 엄격한 시판 전 승인. 이번 단계에서는 보통 해당 없음" |
| Q-Sub | "서류를 만들기 전에 FDA와 하는 사전 상담" |
| 513(g) | "이 제품이 어떤 분류인지 FDA에 글로 물어보는 것" |
| PSG | "병원에서 하룻밤 자며 뇌파·호흡을 재는 표준 수면검사" |
| AHI | "한 시간에 호흡이 멈추는 횟수" |
| SaMD | "의료 목적의 소프트웨어" |
| QMSR | "설계·검증·위험관리 문서를 남기는 품질관리 규정" |

## 용어 사전

| 용어 | 쉬운 말 | 주의 |
|---|---|---|
| 510(k) | FDA의 시판 전 허가 절차 | "cleared"이지 "approved" 아님 |
| predicate | 비교 대상이 되는 이미 허가된 제품 | 같은 code라고 자동 predicate 아님 |
| substantial equivalence | predicate와 "본질적으로 동등"하다는 판단 | intended use + 기술 특성 비교 |
| De Novo | predicate가 없을 때 새 분류를 만드는 절차 | 이번 케이스는 보통 불필요 |
| PMA | 가장 엄격한 시판 전 승인 | Class III |
| SaMD | 의료 목적 소프트웨어 | 하드웨어 없이 동작 |
| CDS | 의사 결정을 돕는 소프트웨어 | patient-facing이면 보통 device |
| general wellness | 질환과 무관한 건강 습관 기능 | treatment claim이면 빠짐 |
| intended use | 이 제품이 하겠다고 선언한 목적 | 광고 문구가 곧 claim |
| indication | 어떤 질환/대상에게 쓰는지 | population 포함 |
| Q-Sub | FDA와의 사전 상담 | 허가 아님 |
| 513(g) | 분류·요건을 묻는 서면 질의 | 60일, 수수료 |
| PSG | 수면다원검사 | apnea 진단의 표준 |
| AHI | 무호흡-저호흡 지수 | 임상 endpoint로 자주 씀 |
| OSA | 폐쇄성 수면무호흡 | obstructive sleep apnea |
| QMSR | 품질관리시스템 규정 | 2026-02-02 발효 |
| design controls | 설계관리 | ISO 13485 7.3 |
| V&V | 검증·타당성 확인 | SRS/SDS, 시험 |
| risk management | 위험관리 | ISO 14971 |
| cybersecurity | 사이버보안 | SBOM, 취약점 대응 |
| human factors | 사용적합성 | OTC 라벨 이해도 |
| PCCP | 사전 변경관리계획 | AI 모델 업데이트 |
| HIPAA | 미국 건강정보 보호법 | B2B/provider 계약 시 |
| PHI | 보호 건강정보 | HIPAA 적용 대상 |
| PII | 개인식별정보 | PHI보다 넓음 |
| BAA | 업무 제휴 계약 | cloud/LLM vendor |
| covered entity | HIPAA 적용 대상 기관 | 병원, 보험사 |
| business associate | 업무 제휴자(BA) | 병원 대신 PHI 처리 |
| breach | 유출/침해사고 | 60일 내 통지 |
| de-identification | 비식별화 | Safe Harbor 18개 식별자 |
| enforcement discretion | 집행 재량 | 구속력 없음 |

## 역할 이름은 한국어로

영어 역할명을 그대로 쓰면 초보자는 뜻을 모른다. 표·제목·문장에서 **한국어를
먼저** 쓰고, 영어는 첫 설명 뒤 괄호로만 붙인다.

| 영어 | 초심자에게 이렇게 |
|---|---|
| covered entity | HIPAA 적용을 받는 병원·보험사 |
| business associate (BA) | 병원 대신 환자정보를 다루는 업체 |
| subcontractor BA | 우리가 다시 맡기는 업체 (클라우드·LLM·문자 발송) |
| BAA | 환자정보 처리 계약 |
| PHI | 병원이 다루는 개인 건강정보 |
| PII | 개인을 알아볼 수 있는 정보 |
| predicate | 비교 대상이 되는 선배 제품 |
| intended use | 이 제품이 하겠다고 신고한 목적 |
| 510(k) | 시판 전 허가 |
| De Novo | 새 분류를 만드는 절차 |
| Q-Sub | FDA 사전 상담 |
| 513(g) | 분류를 묻는 서면 질의 |
| CDS | 의사 결정을 돕는 소프트웨어 |
| PCCP | AI 변경을 미리 정해두는 계획 |

**나쁜 예**

> 우리는 business associate이고, subcontractor BA를 둡니다.

**좋은 예**

> 우리는 병원 대신 환자정보를 다루는 업체예요. 클라우드·LLM 업체는 우리가
> 다시 맡기는 업체고요.

## 추상어를 쓰지 않는 방법

"intended use가 같고 기술적 특성이 비슷하면 가능합니다" 같은 문장은 초심자에게
**금지**한다. 이 문장은 전문용어 4개(intended use, 기술적 특성, predicate,
pathway)를 설명 없이 쓰고, "같다/다르다"의 기준도 주지 않는다.

항상 세 가지 질문으로 바꾼다.

1. **무엇을** 치료/관리한다고 말하나?
2. **누구에게** 쓰나?
3. **어떻게** 전달하나? (앱/웨어러블/처방/비처방)

그리고 표로 보여준다.

| 항목 | 선배 제품 | 우리 제품 | 판단 |
|---|---|---|---|
| 무엇을 | 만성 불면증 | 만성 불면증 | 같음 |
| 누구에게 | 18세 이상 | 18세 이상 | 같음 |
| 어떻게 | 앱 CBT-I + 처방 | 앱 CBT-I + 비처방 | **다름** |
| 주장 | 치료 | 습관 개선 | **다름** |

**결론 문장 예:** "세 가지 중 '처방'과 '주장'이 다릅니다. 그래서 같은 비교
대상을 그대로 쓸 수 없고, 비처방 모델에 맞는 다른 비교 대상을 찾거나 추가
임상을 준비해야 합니다."

### 나쁜 예 / 좋은 예

**나쁜 예**

> intended use가 같고 기술적 특성이 비슷하면 가능합니다. 다르면 다른
> predicate/pathway가 필요합니다.

**좋은 예**

> 경쟁사 앱은 "18세 이상 만성 불면증을, 앱 CBT-I로, 처방을 받아 치료"하는
> 제품으로 허가받았습니다. 우리 앱이 이 세 가지와 같으면 그 앱을 **비교
> 대상**으로 쓸 수 있습니다.
>
> 우리는 **처방 없이** 팔고, 광고 문구도 **"습관 개선"** 입니다. 두 가지가
> 다르므로 같은 비교 대상을 그대로 쓸 수 없습니다. 비처방·습관 개선에 맞는
> 비교 대상을 찾거나, 처방·치료 모델로 제품을 바꿔야 합니다.

## 보내기 전 자체 점검

- [ ] 첫 3문장 안에 결론이 있는가?
- [ ] 설명 없이 쓴 전문용어가 있는가? (`predicate`, `intended use`,
      `technological characteristics`, `pathway`, `substantial equivalence`,
      `SaMD`, `CDS`)
- [ ] "같다/다르다"를 표로 보여줬는가?
- [ ] 다음 행동이 3개 이하인가?
- [ ] 영어 원문을 읽어야 한다면 어느 섹션인지 알려줬는가?
- [ ] 영어 역할명을 설명 없이 썼는가?
- [ ] 소리 내어 읽었을 때 자연스러운가?
- [ ] 한 문장이 40자를 넘는가?

전문용어를 꼭 써야 하면 **같은 문장 안에서** 풀어 쓴다. 예:
"predicate(비교 대상이 되는, 이미 허가된 선배 제품)".


**Before (전문용어 위주 — 초심자에게 부적합)**

> QZW(868.2378, Class II)로 510(k)를 진행하고, predicate는 DEN230041/K240929를
> 사용합니다. INDICATIONS FOR USE의 "assess risk" 범위를 확인하고 Q-Sub을
> 제출하세요.

**After (beginner mode)**

> **한 줄 결론:** 이 기능은 미국에서 "의료기기 소프트웨어"로 규제됩니다. 지금
> 기획대로면 **510(k)(미국 FDA의 시판 전 허가)** 를 받아야 하고, 새 분류를
> 만드는 De Novo까지는 필요 없습니다.
>
> **왜 그런가:** Apple과 Samsung이 이미 비슷한 "수면무호흡 위험 알림" 기능을
> FDA 허가(cleared)받았습니다. 우리 제품은 그 **선배 제품(predicate)** 과
> 본질적으로 같다는 것을 증명하면 됩니다.
>
> **지금 해야 할 일:**
> 1. 광고 문구를 "진단"이 아니라 **"위험을 알려준다"** 로 확정
> 2. Apple `K240929`와 Samsung `K261011`의 `Indications for Use`만 읽기
> 3. 그 문구를 기준으로 Q-Sub(사전 상담) 미팅 질문지 작성

## 하지 말 것

- CFR 인용부터 쏟아내기. 초심자에게는 결론과 다음 행동이 먼저다.
- 한 문장에 약어 3개 이상 넣기.
- "it depends"로 끝내기. 어떤 사실이 확인되면 답이 바뀌는지 명시한다.
- 영어 원문 전체를 번역해 붙이기. 필요한 섹션만 짚어준다.
- 모르는 제품 사실을 추정해서 채우기. "가정"이라고 표시한다.
